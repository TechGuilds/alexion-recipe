# Authentication and personalization

Inventory identity provider, session/cookie usage, roles, protected endpoints, antiforgery checks and presentation rules separately. Record the source branch conditions and representative authorized/unauthorized behavior without storing tokens or user records.

A React conditional cannot replace server authorization. Map protected data access to an approved target backend/session contract; keep secrets on the server. Preserve login/logout/return URL and denied/expired-session behavior. Missing identity integration is an explicit dependency, not a placeholder success.

For XMC, do not assume XP xDB/rules/marketing automation migrate with content. Record rule conditions/actions and target strategy for each; route unsupported behavior to the hub for a decision. A default-layout capture does not cover all variants.

For xpmvc2xpheadless, existing XP services may remain but Layout Service rule evaluation and headless identity behavior still need verification on the selected version. Do not apply XMC exclusions automatically. See [XP target](target-xp-headless.md).

Evidence includes the rule/endpoint inventory, source-to-target disposition, representative cases and unresolved owner. Gate 3 fails when protected data or behavioral branches silently disappear.
