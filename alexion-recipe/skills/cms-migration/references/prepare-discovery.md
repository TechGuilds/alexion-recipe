# Prepare the visible Discovery plan

Use plain phase titles such as `Setup` and `Discovery`. Do not add numbered prefixes or migration-name suffixes (for example, `— Website migration`). Use numeric `rank` for ordering and artifact/binding IDs for identity, not title decorations. Never adopt an unrelated same-name epic; if find-or-create returns a collision, report it rather than silently linking it or inventing a decorated title.

This procedure runs inside `setup.prepare-discovery`, owned by the orchestrator after a verified successful `setup.audit`. It does not require a `phase-continuation` decision: creation of the initial read-only Discovery plan is part of the authorized Setup work, not authorization to execute that plan. Reuse complete context, the current migration artifact, audit evidence and the existing five-task Setup bindings. Missing audit success or context completeness returns to the corresponding Setup task.

1. Read the active domain profile's Discovery procedure and workflow asset. Select tasks applicable to the confirmed migration type, full-migration or discovery-only mode, and agreed sides/surfaces. Do not copy one platform profile’s task list into another migration profile. Omit explicitly excluded work and adjust its dependency edges; missing requested inputs are not scope exclusions.
2. Resolve bound Discovery IDs first. Reuse this migration's existing phase and tasks, preserving completed work and evidence. Never adopt an unrelated phase by name. After an uncertain write, recover the scoped outcome and retry only missing creations or links. Keep the rest of the active workflow intact.
3. Create the Discovery epic when missing, dependent on the actual Setup epic ID. Retain the returned ID. Append only this ID to artifact `content.phases`, preserving all existing links and unrelated content. Use validated artifact tools. Set explicit numeric phase ranks: the UI sorts `rank` ascending, then name, not dependency order or numbered titles. Missing ranks sort last. If the bound Setup phase has no finite rank, set Setup to `1000`; otherwise preserve its existing rank. Set Discovery to the Setup rank + 1000 when creating it or when its current rank is missing or not greater than Setup. Preserve an existing valid later Discovery rank and never reorder unrelated project epics. A find-or-create result may be unchanged, so use update-epic when rank repair is needed.
4. Create each applicable task with the profile's exact workflow key, complete profile-owned instructions and acceptance criteria, actual artifact/phase/prerequisite references and a qualified agent. Use role references instead of copied connector configuration. A fully defined executable procedure uses `todo`, even if it waits for another task's outputs. Use `draft` only when missing task-specific inputs or unresolved scope prevent a truthful actionable description, such as a requested source-code repository. Record the missing input, owner and next action in that description. Never use placeholders or fabricate missing choices. A clear draft task is a valid planning deliverable, not a failed Setup audit.
5. Persist returned phase/task IDs in `reports/kajoo-workflow-bindings.json`. Append or reconcile Discovery in the active `workflow.json`; preserve all five Setup tasks and existing statuses. Entry tasks depend on `setup.prepare-discovery`. Map todo to `pending` and draft to `blocked`, with the precise missing-input reason in `reports/discovery-plan.json`. These sandbox statuses do not authorize dispatch. Keep already completed tasks unchanged and never demote them on a planning retry.
6. Save `reports/discovery-plan.json` with artifact/profile/scope identity, audit evidence reference, phase/task IDs and phase ranks, workflow keys, ready/draft classification, missing inputs and owners, and `executionAuthorized: false` until a current explicit continuation is verified. Validate the full workflow and read back both phase ranks (Discovery greater than Setup), the Kajoo tasks, bindings and artifact links. Only then mark `setup.prepare-discovery` done in both stores. Setup is now complete while Discovery remains unstarted.

Do not dispatch Discovery or run its probes/analysis in this task. Pause or no answer leaves the visible plan intact. A new-chat choice leaves execution for that chat. After planning succeeds, present the plan and ask for the separate scoped execution continuation using [Discovery entry](start-discovery.md). Later evidence-led migration workflow proposals still require their existing `workflow-plan` approval; this initial Discovery planning task does not bypass that gate.
