# Existing-work validation probe

Before adopting apparent existing work, inspect it independently rather than trusting old task journals.

- Code: compare actual component/layout files, source mapping and current browser/test evidence.
- Content: confirm target content-space/item identities, representative records at different depths, expected fields and locale/version scope.
- Each additional workstream: use the active profile's checks for the applicable target structures, integrations, and source-to-target contract.

Return observed matches, missing evidence and mismatches. The coordinator may reconcile proven technical completion into workflow tasks, but historic approvals stay pending unless an explicit scoped user decision is available. Do not call deleted status/state tools or directly edit DB configuration.
